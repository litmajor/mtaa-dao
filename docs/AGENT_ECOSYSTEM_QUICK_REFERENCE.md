## 🔐 PAYMENT METHODS

### Dual-Pricing System

```
USER CHOICE
     ↓
┌────────────────────────────────────────┐
│   Pay in KES (M-Pesa) or MTAA (Token)  │
└─────────────┬──────────────────────────┘
              ↓
        ┌─────────────────┐
        │ KES (Fiat)      │ MTAA (Crypto)
        │ M-Pesa Gateway  │ Direct Transfer
        │ Rate: Dynamic   │ Rate: Oracle
        │ Off-ramp ready  │ On-chain native
        └─────────────────┘
```

**Exchange Rate**: 1 MTAA = 15 KES (dynamic oracle)

**Example**: 150,000 KES subscription
- Via M-Pesa: Pay 150,000 KES to gateway
- Via MTAA: Pay 10,000 MTAA (~150K KES equivalent)

## 📊 SUBSCRIPTION VERIFICATION

### Universal Function for All Agents

```solidity
function isSubscribed(bytes32 agentId, address user) 
  external 
  view 
  returns (bool subscribed, uint256 tier)
```

**Called on every agent interaction:**
1. User attempts to use agent
2. Agent calls `isSubscribed(agentId, user)`
3. If subscribed + active + not expired → Grant access
4. If not → Show tier options
5. Log attempt in audit trail

## 🔄 WORKFLOW: User → Agent → Revenue

```
1. USER ACTION
   ↓
2. isSubscribed(agentId, user)?
   ├─ YES → Continue
   └─ NO → Show upgrade prompt
   ↓
3. AGENT EXECUTION
   ├─ Read permission checks
   ├─ Execute operation
   ├─ Write audit log
   └─ Calculate fee
   ↓
4. PAYMENT PROCESSING
   ├─ Collect fee (MTAA or KES)
   ├─ Store transaction
   └─ Calculate revenue split
   ↓
5. REVENUE DISTRIBUTION
   ├─ Agent gets 40-50%
   ├─ Platform gets 25-30%
   ├─ Treasury gets 15-20%
   └─ Community gets 10%
   ↓
6. AUDIT & SETTLEMENT
   ├─ Log transaction
   ├─ Update agent earnings
   └─ Update subscriber balance
```

## 🎓 KEY CONCEPTS

### Agent
An autonomous or semi-autonomous entity that performs specific functions, requires subscription verification, and earns revenue from usage.

### Subscription
A paid agreement allowing a user to access an agent for a specific tier duration (monthly).

### Tier
A subscription level (FREE, BASIC, PREMIUM, ENTERPRISE) defining price and access to agents.

### Revenue Split
Distribution of agent usage fees among agent, platform, treasury, and community.

### Audit Log
Immutable record of all agent actions for compliance and transparency.

### Governance
Democratic voting system for critical agent actions requiring DAO approval.
