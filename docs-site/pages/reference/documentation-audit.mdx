# Documentation audit

This is the reconciliation record for the documentation rebuild: what exists, what
survived contact with the code, and what did not. It covers two corpora:

- `docs/` — the historical engineering corpus, **1,504 Markdown files** (1,490 of them in
  the flat top-level directory), 1,522 files in total across 7 directories, ~23 MB.
- `docs-site/` — the published Nextra site, **91 MDX pages** before this pass.

## Method

Claims were checked against source, not against other documents. The primary evidence is:

| Question | Evidence |
| --- | --- |
| Which endpoints exist? | Walking `server/index.ts` + `server/routes.ts` and every `use()` mount |
| What is the schema? | `pgTable` declarations in `shared/*.ts` |
| Which contracts exist? | `contracts/**/*.sol` |
| What configuration exists? | `shared/config.ts` (Zod schema) |
| How is it deployed? | `docker-compose.yml`, `nginx.conf`, `.github/workflows/` |
| What is installed? | `package.json` |

`node docs-site/scripts/generate-reference.mjs` reproduces the machine-derived parts.

## Headline corrections

| Previous claim | Where it appeared | Finding |
| --- | --- | --- |
| "364+ API endpoints" | root `README.md` | **Understated.** 1,206 statically resolvable endpoints under `/api`, `/walletapi`, `/health`, `/metrics`. |
| "`/api/dao`, `/api/vaults`, `/api/proposals` are the core endpoints" | root `README.md` API overview | **Stale.** `/api/vaults` and `/api/tokens` return `410 Gone`; DAO traffic belongs on `/api/v1/daos`. See [Deprecated APIs](/reference/deprecated). |
| `https://api.mtaadao.com/v1` base URL | 4 docs-site developer pages, 5 `docs/` files | **Unverified.** No such host, domain or public base URL appears anywhere in the code or infrastructure config. The server binds `PORT` (default 5000) behind Nginx. |
| `sk_live_...` API keys via `Authorization: Bearer` | 4 docs-site developer pages | **Contradicted.** The implemented scheme is a JWT `access_token` cookie (fallback: `Bearer` JWT) plus a CSRF double-submit header. An `api_keys` table exists but no request-authenticating middleware reads it. |
| `@mtaadao/sdk` npm package (JS + Python) | 4 docs-site developer pages | **Unverified.** No SDK source, build target, or publish workflow exists in this repository. |
| OAuth 2.0 authorization-code flow at `auth.mtaadao.com` | `developer/authentication.mdx` | **Contradicted.** Only Google OAuth login exists, at `GET /api/auth/oauth/google` and its callback. There is no first-party OAuth provider. |
| Rate-limit tiers "Free 100/min, Pro $99/mo 1,000/min" | `developer/rate-limits.mdx` | **Unverified.** The implemented limits are per-operation (e.g. withdrawals 10/hour, deposits 20/hour, order execution 100/min) plus a global `RATE_LIMIT_MAX_REQUESTS` default of 100 per 15-minute window. No tiered commercial plan is enforced in code. |
| Vault documentation describing `/api/vaults` | 48 files in `docs/` | **Stale**, path removed. |
| Yuki documentation describing `/api/yuki` | 64 files in `docs/` | **Stale**, path now `307`-redirects to `/api/v1/yuki`. |

### Duplication

52 filename families contain more than one document (113 files total), typically the
`X`, `X_COMPLETE`, `X_SUMMARY`, `X_INDEX` pattern — for example three separate
`ADMIN_SYSTEM_PHASE_3_*` documents and three `MORIO_DATA_HUB_*` documents. These are
sequential drafts of the same work, not complementary documents.

## Defects found while auditing

Documented, not fixed — this pass changed no application behaviour.

| # | Finding | Evidence | Severity |
| --- | --- | --- | --- |
| 1 | `GATEWAY_MODE` defaults to `live`; any value other than the exact string `stub` enables live Celo execution, and it is not part of the validated env schema | `server/services/gatewayAggregator.ts:1477` | High |
| 2 | Three Socket.IO servers construct without a `path`, so they collide on the default `/socket.io/` if attached to the same HTTP server. The `WS_PATHS` constants exist but are not applied | `server/websocket/websocket-events.ts` header comment | Medium |
| 3 | The Docker healthcheck targets `/health`, which `301`-redirects to `/api/health`; `curl -f` does not follow it, so the check passes on a redirect rather than a health response | `docker-compose.yml`, `server/routes.ts` | Medium |
| 4 | Every `Sunset` header is `Date.now() + 90d` evaluated per request, so no deprecation ever actually sunsets | `server/routes.ts` (all tombstones) | Low |
| 5 | `api_keys` / `api_quotas` tables exist with hashing, prefixes, IP allow-lists and per-key rate limits, but no middleware authenticates a request from them — the documented API-key auth flow has storage but no enforcement path. (`/api/settings/api-keys` manages *exchange* credentials in `exchange_api_keys`, a different table.) | `shared/securityEnhancedSchema.ts:177` vs `server/middleware/*` | Medium |
| 5b | `createApiKey` in `server/storage/storage-low-priority.ts` inserts columns that do not exist on `api_keys` (`keyName`, `allowedIps`, `allowedOrigins`, `rateLimitRequests`, `rateLimitWindow`, `description`, `metadata`, `usageCount`); the table defines `name`, `ipWhitelist`, `rateLimit`. The helper cannot succeed as written | `server/storage/storage-low-priority.ts:337-375` | Medium |
| 5c | `/api/proposal-execution` is registered three times — a live router, a `307` rewrite, and a `410 Gone` — so its behaviour depends on boot-time mount order | `server/routes.ts:449,511`, `server/index.ts:1525` | Low |
| 5d | Rate limiting is opt-in per route: `globalRateLimiter` is never mounted, `RATE_LIMIT_WINDOW_MS`/`RATE_LIMIT_MAX_REQUESTS` are parsed but never consumed, `capitalFlowMiddleware.ts` is imported by no route, and the entire `server/routes/yuki.ts` router (with its swap/bridge/flash-loan limiters) is unmounted. `checkRateLimit` also fails open when Redis errors | `server/middleware/*`, `shared/config.ts:226` | High |
