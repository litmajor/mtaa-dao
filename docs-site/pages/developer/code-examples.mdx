# Code examples

Every example below is written against a handler in `server/routes/**`, with the field names
that handler reads and the response it returns. Base URL is the development one
(`http://localhost:5000/api`); substitute the deployed base from
[API reference](/developer/api-reference).

<Callout type="warning">
  There is no client SDK and no API key. These examples authenticate the way the frontend
  does — cookie JWT plus a double-submit CSRF header. See [Developer hub](/developer) for why.
</Callout>

## Setting up a session

```bash
BASE=http://localhost:5000/api

curl -s -X POST "$BASE/auth/login" \
  -H 'Content-Type: application/json' \
  -c cookies.txt \
  -d '{"email":"you@example.com","password":"..."}'

CSRF=$(grep csrf_token cookies.txt | awk '{print $7}')
```

Reuse `cookies.txt` and `$CSRF` in every call below. Refresh with
`POST /auth/refresh-token` when the 15-minute access token expires.

## List the DAOs you can see

`GET /api/v1/daos` — `isAuthenticated`.

```bash
curl -s "$BASE/v1/daos" -b cookies.txt
```

## List proposals in a DAO

`GET /api/v1/daos/:daoId/proposals` — inherits `isAuthenticated` and DAO-id validation from
the `_daoId` router. Query parameters read by the handler: `status`, `proposer`, `sortBy`,
`sortOrder`, `limit` (default 50), `offset` (default 0).

```bash
curl -s "$BASE/v1/daos/$DAO_ID/proposals?status=active&limit=20" -b cookies.txt
```

Response:

```json
{
  "success": true,
  "data": [ { "id": "...", "title": "...", "status": "active", "yesVotes": 0 } ],
  "pagination": { "total": 42, "limit": 20, "offset": 0, "hasMore": true }
}
```

<Callout type="info">
  `sortBy`/`sortOrder` are accepted but the handler always orders by `createdAt` descending,
  and `total` is computed by selecting every matching row. Expect both to change.
</Callout>

## Create a proposal

`POST /api/v1/daos/:daoId/proposals`. Rate limited to **10 per hour** per user
(`proposal:create:<userId>`). Required: `title`, `description`, `voteEndTime`. Optional:
`proposalType` (default `general`), `quorumRequired` (default 100), `pollOptions`,
`allowMultipleChoices`, `executionData`, `tags`, `imageUrl`.

```bash
curl -s -X POST "$BASE/v1/daos/$DAO_ID/proposals" \
  -b cookies.txt -H "X-CSRF-Token: $CSRF" \
  -H 'Content-Type: application/json' \
  -d '{
    "title": "Fund community borehole",
    "description": "Allocate treasury funds for the water project",
    "voteEndTime": "2026-09-01T00:00:00.000Z",
    "proposalType": "general",
    "quorumRequired": 100,
    "tags": ["infrastructure"]
  }'
```

Authorization is enforced **inside** the handler, not by middleware: you must be a member of
the DAO, and your membership role must be one of `admin`, `proposer`, `elder`, `creator`.
Otherwise you get `403`.

| Status | Body |
| --- | --- |
| `201` | `{ "success": true, "data": { ...proposal } }` |
| `400` | `{ "error": "Missing required fields: title, description, voteEndTime" }` |
| `401` | `{ "error": "User not authenticated" }` |
| `403` | `{ "error": "You are not a member of this DAO" }` or `"You do not have permission to create proposals"` |

Side effect: after responding, the handler enqueues a `proposal-created` email to every DAO
member with an address, linking to `${FRONTEND_URL}/dao/:daoId/proposals/:id`.

## Vote

`POST /api/v1/daos/:daoId/proposals/:proposalId/vote`. Rate limited to **30 per minute** per
user. Body: `vote` (`yes` | `no` | `abstain`) and optional `isAnonymous`.

```bash
curl -s -X POST "$BASE/v1/daos/$DAO_ID/proposals/$PROPOSAL_ID/vote" \
  -b cookies.txt -H "X-CSRF-Token: $CSRF" \
  -H 'Content-Type: application/json' \
  -d '{"vote":"yes"}'
```

```json
{ "success": true, "vote": "yes", "isAnonymous": false, "pointsAwarded": 5 }
```

Behaviour worth knowing before you build on it:

- One vote per user per proposal; a second attempt returns `400 Already voted on this proposal`.
- Voting power is hard-coded to `'1'` in this handler — it does not read stake or reputation.
- `isAnonymous: true` stores the vote under the literal user id `guest` and awards no points.
- The proposal counter is incremented with a SQL `+ 1`; the insert and the increment are not
  in one transaction.

## Read market data

`GET /api/v1/yuki/market/prices` returns oracle prices for a comma-separated `symbols`
query (defaults to `BTC/USD,ETH/USD`). The oracle's source cascade, caching and staleness
rules are in [Market data](/trading/market-data).

```bash
curl -s "$BASE/v1/yuki/market/prices?symbols=BTC/USD,CELO/USD" -b cookies.txt
```

```json
{
  "BTC/USD": {
    "symbol": "BTC/USD",
    "price": 0,
    "currency": "USD",
    "timestamp": "2026-08-13T00:00:00.000Z",
    "source": "priceOracle",
    "confidence": 0.95
  }
}
```

<Callout type="error">
  `confidence` is the literal constant `0.95`, not a computed figure, and the optional
  `include_charts=true` payload is **synthetic** — `high24h`/`low24h` are the spot price
  ±5% and `change24h` is `Math.random()`. Do not display it as market history.
</Callout>

Confirm the exact path for your build in [Trading & market data](/reference/api/trading) —
several trading route files exist in the repo that are **not** mounted.

## JavaScript equivalent

```javascript
const BASE = 'http://localhost:5000/api';

// The browser sends the cookies; read the CSRF cookie and echo it back.
const csrf = document.cookie.split('; ').find((c) => c.startsWith('csrf_token='))?.split('=')[1];

const res = await fetch(`${BASE}/v1/daos/${daoId}/proposals`, {
  method: 'POST',
  credentials: 'include',
  headers: { 'Content-Type': 'application/json', 'X-CSRF-Token': csrf ?? '' },
  body: JSON.stringify({ title, description, voteEndTime }),
});

const body = await res.json();
if (!res.ok) throw new Error(body.error?.message ?? body.error ?? 'Request failed');
```

Note the two error shapes: handlers that throw reach the central error handler and return
`{ success: false, error: { message, code, ... } }`, while the handlers above return a bare
`{ error: "..." }` string. Handle both.
