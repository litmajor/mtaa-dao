# Working with agents

MtaaDAO runs a small in-process agent registry (`server/agents/**`) plus the Morio
conversational layer. This page covers the developer-facing surface. For what each agent
actually does internally, its lifecycle and its known gaps, read
[Agent runtime](/reference/agents).

<Callout type="error">
  **You cannot define a custom agent over the API.** Agent *types* are a closed enum compiled
  into the server — `trading`, `anomaly_detection`, `compliance`, `governance_analytics`.
  `POST /api/agents` instantiates one of those types; it does not accept a strategy, a
  trigger schedule, spending limits or user-supplied code. Earlier documentation showed a
  `dao.agents.create({ strategy, trigger, limits })` SDK call — no such SDK, endpoint or
  fields exist. Adding a new agent means writing a class in `server/agents/` and deploying it.
</Callout>

## Capability matrix

| Capability | Status | Evidence |
| --- | --- | --- |
| List, inspect and monitor running agents | `SUPPORTED` | `GET /api/agents`, `/api/agents/:agentId`, `/api/agents/status/summary` |
| Instantiate one of the four built-in agent types | `SUPPORTED` (admin only) | `POST /api/agents`, `requireAdmin` |
| Pause / resume / shut down an agent | `SUPPORTED` (admin only) | `POST /api/agents/:agentId/{pause,resume,shutdown}` |
| Read per-domain agent metrics | `SUPPORTED` | `/api/agents/metrics/{trading,anomalies,governance}` |
| Conversational analysis via Morio | `PARTIALLY IMPLEMENTED` | `/api/morio/*`; the committed config falls back to a mock LLM |
| User-defined strategies, triggers or spending limits | `PLANNED` | No route, no schema, no executor |
| Autonomous on-chain execution by the registry trading agent | `PLANNED` | Its route executor is a no-op returning an empty tx hash |
| Outbound webhooks on agent events | `PLANNED` | No subscription API |

## Inspect what is running

```bash
curl -s "$BASE/agents" -b cookies.txt
curl -s "$BASE/agents/status/summary" -b cookies.txt
curl -s "$BASE/agents/type/trading" -b cookies.txt
curl -s "$BASE/agents/metrics/trading" -b cookies.txt
```

All require `isAuthenticated`. `GET /api/agents/:agentId` returns the registry record plus
`instance.getMetrics()`, `createdAt` and `lastActive`.

## Create an agent (admin)

`POST /api/agents` — `requireAdmin`, plus an agent-mutation rate limiter.

```bash
curl -s -X POST "$BASE/agents" \
  -b cookies.txt -H "X-CSRF-Token: $CSRF" \
  -H 'Content-Type: application/json' \
  -d '{
    "type": "trading",
    "agentId": "trading-primary",
    "registerOnChain": false
  }'
```

Body fields the handler reads:

| Field | Default | Meaning |
| --- | --- | --- |
| `type` | required | One of `trading`, `anomaly_detection`, `compliance`, `governance_analytics` |
| `agentId` | generated | Canonical id |
| `registerOnChain` | `false` | Attempt on-chain registration and payment configuration |
| `agentAddress` | — | On-chain address used when `registerOnChain` is true |
| `agentName`, `description`, `category`, `autonomyLevel`, `paymentConfig` | `''`/`0`/`{}` | Registration metadata |

`400` if `type` is missing or not in the enum. The error message enumerates the valid types.

## Lifecycle control

```bash
curl -s -X POST "$BASE/agents/$AGENT_ID/pause"    -b cookies.txt -H "X-CSRF-Token: $CSRF"
curl -s -X POST "$BASE/agents/$AGENT_ID/resume"   -b cookies.txt -H "X-CSRF-Token: $CSRF"
curl -s -X POST "$BASE/agents/$AGENT_ID/shutdown" -b cookies.txt -H "X-CSRF-Token: $CSRF"
```

All three are `requireAdmin`. State lives in the process registry, so it does not survive a
restart — the boot sequence re-instantiates the standard agent set.

## Morio

`/api/morio/chat`, `/analyze`, `/assess-risk`, `/confirm-action`, `/user-context`,
`/session/:userId`, `/stream/:jobId` — all behind `isAuthenticated` and `authenticateToken`.
`/api/morio/health` is unauthenticated.

<Callout type="warning">
  The committed `config/morio-llm.json` selects `provider: "ollama"`. The provider factory
  only recognises `openai` and `mock`, and logs a warning before returning the **mock**
  provider for anything else. Unless you construct Morio with `provider: "openai"` and a key,
  responses come from the mock. Treat Morio output as non-authoritative.
</Callout>

`POST /api/morio/confirm-action` exists because Morio does not execute financial actions on
its own — a proposed action is returned to the user and must be confirmed.

## Real-time agent events

Two transports are relevant: `/ws/coordinator` and `/ws/morio`. Event names and payloads are
in [WebSocket events](/reference/websocket-events).

## Writing a new agent type

There is no plugin boundary. A new agent is a class extending the abstract base in
`server/agents/`:

```ts
abstract initialize(): Promise<void>;
abstract process(data: unknown): Promise<unknown>;
```

You then add its literal to the `AgentType` union, register it in the factory and, if it
should start with the server, add it to the boot list. That is a code change to the server,
reviewed and deployed like any other — not a runtime registration.
