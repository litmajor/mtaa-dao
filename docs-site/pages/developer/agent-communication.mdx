# Agent communication

Agents communicate through an in-process message bus:
`server/core/agent-framework/message-bus.ts`. It is a `MessageBus extends EventEmitter`
singleton (`messageBus`) imported directly by each agent — `analyzer`, `defender`,
`synchronizer`, `trading`, `compliance`, `governance`, `anomaly-detection`, `morio` — and by
`server/services/stableRiskMonitorService.ts`.

<Callout type="warning">
  **It is in-memory and single-process.** No Redis, no broker, no persistence. Messages do not
  cross process or container boundaries, history is lost on restart, and running more than one
  API replica gives each replica its own isolated bus. Any earlier description of a
  distributed or durable bus was aspirational.
</Callout>

<Callout type="info">
  Two other files are also named `message-bus.ts` — `server/core/elders/coordinator/` and
  `server/core/agents/gateway/`. They are separate buses for those subsystems, not the same
  instance. Nothing bridges them.
</Callout>

## Message shape

```ts
export type MessagePriority = 'low' | 'medium' | 'high' | 'critical';

export interface AgentMessage {
  id: string;
  from: string;
  to: string | string[];   // agent id, list of ids, or the literal 'broadcast'
  type: MessageType;
  payload: any;
  timestamp: Date;
  priority: MessagePriority;
  requiresResponse: boolean;
  correlationId?: string;
  ttl?: number;            // milliseconds
}
```

<Callout type="warning">
  `priority` and `ttl` are carried on the message but **not acted on** by the bus: delivery is
  not ordered by priority and expired messages are not dropped. Treat them as metadata until
  the bus enforces them.
</Callout>

## Message types

`MessageType` is a single enum grouped by originating subsystem.

| Group | Values |
| --- | --- |
| Analyzer | `fraud_alert`, `anomaly_detected`, `treasury_health`, `risk_assessment`, `node_profile` |
| Synchronizer | `state_sync`, `drift_detected`, `rollback_request`, `checkpoint_created`, `sync_beat` |
| Defender | `threat_detected`, `quarantine_user`, `release_user`, `ethical_review`, `defense_action` |
| AI layer | `analysis_request`, `analysis_response`, `action_required`, `notification`, `user_query` |
| System | `agent_online`, `agent_offline`, `health_check`, `metrics_update`, `alert_request`, `price_update`, `liquidity_update`, `execution_request`, `transaction_event`, `user_event`, `audit_request` |

## API

```ts
subscribe(agentId: string, messageTypes: MessageType[], handler: MessageHandler): void
unsubscribe(agentId: string, messageTypes?: MessageType[]): void
publish(message: AgentMessage): Promise<void>
request(message: AgentMessage, timeout = 5000): Promise<any>
respond(correlationId: string, payload: any): Promise<void>
broadcast(type: MessageType, payload: any, sender: string, priority?: MessagePriority): Promise<void>
getHistory(limit?: number): AgentMessage[]
getStats(): { totalMessages; subscriberCount; pendingResponses; messagesByType }
```

### Publish / subscribe

`publish` appends to history, emits a `'message'` event for monitoring, then delivers to
every subscriber of that `type` whose `agentId` matches the `to` field (or where `to` is
`'broadcast'`). Delivery is concurrent and uses `Promise.allSettled`, so **one failing handler
does not stop the others** and the publisher is not told about the failure — it is only
logged.

If no one is subscribed to the type, the bus logs a warning and returns; the message is
silently dropped after being recorded in history.

```ts
import { messageBus, MessageType } from '../core/agent-framework/message-bus';

messageBus.subscribe('my-agent', [MessageType.RISK_ASSESSMENT], async (message) => {
  // handler throwing here is logged, not propagated to the publisher
});
```

### Request / response

`request` sets `requiresResponse`, assigns a `correlationId`, publishes, and returns a promise
that rejects with `Request timeout for <type>` after `timeout` milliseconds (default 5000).
The responder calls `respond(correlationId, payload)`; if no pending request matches, the
response is logged and discarded.

### Broadcast

`broadcast` builds a message with `to: 'broadcast'`, `requiresResponse: false` and default
priority `medium`, then publishes it. It still only reaches subscribers of that specific
`MessageType`.

## Observability

- `getHistory(limit?)` — the last **1,000** messages (`MAX_HISTORY`), oldest evicted first.
- `getStats()` — total messages in history, live subscriber count, pending request count, and
  a per-type message count derived from history (so it is a rolling window, not a lifetime
  total).
- `setMaxListeners(100)` in the constructor, to accommodate many agents.

There is no HTTP endpoint exposing bus history or stats. To observe it in production you read
the logs or add one.
