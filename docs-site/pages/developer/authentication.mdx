# Authentication

Source of truth: `server/auth.ts` (the `authenticate` middleware and token handlers) and
`server/middleware/auth.ts` (`authenticateToken`, used by a smaller set of routers).

<Callout type="warning">
  **This page replaced an earlier version** that described `sk_live_...` API keys, an
  `@mtaadao/sdk` package, and an OAuth 2.0 authorization server at `auth.mtaadao.com`.
  None of those exist in the codebase. See the
  [documentation audit](/reference/documentation-audit) for the full list of corrections.
</Callout>

## The scheme: JWT cookies + CSRF double-submit

Logging in sets three cookies:

| Cookie | `httpOnly` | Lifetime | Purpose |
| --- | --- | --- | --- |
| `access_token` | yes | 15 minutes | The bearer credential |
| `refresh_token` | yes | 7 days | Mints a new access token |
| `csrf_token` | **no** (readable by JS by design) | 15 minutes | Double-submit value |

All three are `sameSite: 'strict'` and `secure` in production. Tokens are JWTs signed
HS256 with `JWT_SECRET` / `JWT_REFRESH_SECRET`.

For any method other than `GET`, `HEAD` or `OPTIONS`, you must read `csrf_token` and echo
it in the `X-CSRF-Token` header. The middleware compares the two and rejects a mismatch
with `403`.

```bash
# 1. Log in — cookies land in the jar
curl -c jar.txt -X POST http://localhost:5000/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","password":"..."}'

# 2. Read requests need nothing else
curl -b jar.txt http://localhost:5000/api/auth/user

# 3. Writes must echo the CSRF cookie into the header
CSRF=$(grep csrf_token jar.txt | awk '{print $7}')
curl -b jar.txt -X POST http://localhost:5000/api/v1/daos \
  -H "X-CSRF-Token: $CSRF" \
  -H 'Content-Type: application/json' \
  -d '{"name":"My DAO"}'
```

### Bearer fallback

`authenticate` falls back to `Authorization: Bearer <jwt>` when no `access_token` cookie is
present. The token is the same 15-minute access JWT — **not** a long-lived API key. CSRF
checking is not conditional on how the token arrived, so a bearer-only client still needs a
matching `csrf_token` cookie and `X-CSRF-Token` header for writes.

<Callout type="info">
  Two middleware families coexist. `server/auth.ts` `authenticate` (aliased
  `isAuthenticated`) is the main one and returns `401` for a bad token.
  `server/middleware/auth.ts` `authenticateToken` is header-only and returns `403` for an
  invalid or expired token and for a pending-2FA temporary token. Which one guards a route
  is visible per endpoint in the [API reference](/reference/api).
</Callout>

## Validation performed on every request

1. Token present (cookie preferred, header fallback) — else `401`.
2. Signature and expiry valid — else `401`.
3. SHA-256 hash of the token is not in the blacklist (`server/services/tokenBlacklist`) — else `401 Token has been revoked`.
4. The user has not globally revoked their tokens — else `401 All tokens revoked`.
5. CSRF double-submit matches, for unsafe methods — else `403 Invalid CSRF token`.

Errors use the shape `{ "success": false, "error": { "message": "..." } }`.

## Endpoints

| Method | Path | Auth | Notes |
| --- | --- | --- | --- |
| `POST` | `/api/auth/register` | none | Rate-limited (`registerRateLimiter`), body sanitized |
| `POST` | `/api/auth/login` | none | Rate-limited (`loginRateLimiter`) |
| `POST` | `/api/auth/verify-otp` | none | Rate-limited (`otpVerifyRateLimiter`) |
| `POST` | `/api/auth/resend-otp` | none | |
| `POST` | `/api/auth/refresh-token` | refresh cookie | **Also requires the CSRF double-submit** |
| `POST` | `/api/auth/logout` | none | Clears all three cookies and blacklists the token |
| `GET` | `/api/auth/user` | `authenticate` | Current user |
| `GET` | `/api/auth/oauth/google` | none | Starts Google OAuth |
| `GET` | `/api/auth/oauth/google/callback` | none | Google OAuth callback |
| `POST` | `/api/auth/telegram-link` | `isAuthenticated` | Links a Telegram account |

Google is the only OAuth provider implemented. MtaaDAO is not an OAuth **provider** — there
is no authorization-code flow for third-party apps to sign users in with MtaaDAO.

## Two-factor authentication and PINs

| Method | Path |
| --- | --- |
| `POST` | `/api/account/2fa/enable`, `/api/account/2fa/disable` |
| `POST` | `/api/v1/settings/2fa/check` |
| `POST` | `/api/account/pin`, `/api/v1/wallets/setup/pin` |
| `GET`/`PUT` | `/api/account/pin-settings` |
| `GET`/`DELETE` | `/api/account/sessions`, `/api/account/sessions/:id` |

While 2FA is pending, `authenticateToken` issues a temporary token that is explicitly
rejected for normal API access (`403`).

## Authorization

Role checks compose on top of authentication:

| Middleware | Effect |
| --- | --- |
| `authorize(roles)` / `requireRole(roles)` | Any of the listed roles |
| `requireAdmin` | `admin`, `super_admin` |
| `requireModerator` | `admin`, `super_admin`, `moderator` |
| `requirePremium` | `admin`, `super_admin`, `premium`, `dao_owner` |
| `requireSuperAdmin` | `super_admin` only |
| `requireDAORole`, `isDaoMember`, `isDaoAdmin` | Membership/role within a specific DAO |
| `requirePermission` | Fine-grained permission string |

Roles come from the JWT claim `roles` (falling back to `role`), accepting either an array
or a comma-separated string. Failing a role check returns
`403 Forbidden: insufficient privileges`.

## API keys

<Callout type="warning">
  **Security Gap / Recommended Control.** The `api_keys` table
  (`shared/securityEnhancedSchema.ts`) models hashed keys, prefixes, permissions, IP
  allow-lists, per-key rate limits, expiry and revocation — but **no middleware
  authenticates an HTTP request from it**. There is currently no programmatic API-key
  authentication path. Machine clients must use the JWT flow above.

  Note that `/api/settings/api-keys` manages *exchange* credentials (`exchange_api_keys`,
  encrypted at rest, secrets never returned) for CEX connectivity. It does not issue
  MtaaDAO platform keys.
</Callout>

## Base URL

There is no public hosted base URL in this repository. The server binds `HOST`:`PORT`
(default `localhost:5000`) and is fronted by Nginx in
[the Docker topology](/operations). Any absolute `api.mtaadao.com` URL you find in older
documentation is unverified.
