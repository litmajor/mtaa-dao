# Developer hub

MtaaDAO is a single Express application (`server/`) with a React/Vite frontend (`src/`),
PostgreSQL via Drizzle, Redis, six WebSocket transports and a set of Solidity contracts under
`contracts/`. Everything a third party can use is the HTTP API and the WebSocket surface —
there is no other integration channel today.

<Callout type="error">
  **There is no MtaaDAO SDK.** No `@mtaadao/sdk` npm package, no Python or Go client, and no
  package directory in this repository. Earlier documentation showed SDK snippets; they never
  corresponded to a published artifact. Use plain HTTP. An SDK is `PLANNED` at most — it is
  not something you can install.
</Callout>

<Callout type="error">
  **There is no API-key issuance flow.** API-key tables exist in the schema, but no mounted
  middleware authenticates a request with an API key and no endpoint issues one to a
  developer. Integrations authenticate as a **user**, with the same cookie/JWT scheme the
  frontend uses.
</Callout>

## Capability matrix

| Capability | Status | Notes |
| --- | --- | --- |
| Call the HTTP API as an authenticated user | `SUPPORTED` | Cookie JWT or `Authorization: Bearer` |
| Subscribe to real-time events over WebSocket | `SUPPORTED` | Six transports, [see the registry](/reference/websocket-events) |
| Machine-to-machine access with an API key | `PLANNED` | Storage exists, enforcement does not |
| Outbound webhooks to your service | `PLANNED` | Webhook *validators* exist for inbound provider callbacks; there is no subscription API for outbound events |
| Official client SDKs | `PLANNED` | Not published |
| Sandbox / test environment | `UNVERIFIED` | A staging base URL is declared in the Swagger config; nothing in this repo provisions or seeds it |
| Run the whole stack locally | `SUPPORTED` | [Local development setup](/developer/setup) |

## Base URL and conventions

`http://localhost:5000/api` in development. Envelopes, error codes and the staging/production
base URLs are documented in [API reference](/developer/api-reference); the full generated
endpoint list is at [/reference/api](/reference/api).

## Authenticate

`POST /api/auth/login` sets three cookies — `access_token` (15 min), `refresh_token`
(7 days) and a JS-readable `csrf_token`. Send the CSRF value back in `X-CSRF-Token` on every
non-safe request.

```bash
curl -i -X POST http://localhost:5000/api/auth/login \
  -H 'Content-Type: application/json' \
  -c cookies.txt \
  -d '{"email":"you@example.com","password":"..."}'

# Authenticated read
curl http://localhost:5000/api/auth/user -b cookies.txt

# Non-safe request: echo the csrf_token cookie back as a header
curl -X POST http://localhost:5000/api/v1/daos \
  -b cookies.txt \
  -H "X-CSRF-Token: $(grep csrf_token cookies.txt | awk '{print $7}')" \
  -H 'Content-Type: application/json' \
  -d '{"name":"My Community DAO"}'
```

Other identity endpoints that exist: `POST /api/auth/register`,
`POST /api/auth/refresh-token`, `POST /api/auth/logout`, `POST /api/auth/verify-otp`,
`POST /api/auth/resend-otp`, `GET /api/auth/oauth/google` and its callback,
`POST /api/auth/telegram-link`. Full list and middleware:
[Identity & accounts](/reference/api/identity).

## The API surfaces

| Surface | What lives there |
| --- | --- |
| [Identity & accounts](/reference/api/identity) | Auth, sessions, 2FA, profiles, KYC |
| [DAO & governance](/reference/api/dao) | DAOs, membership, proposals, voting, chat, contributions |
| [Treasury & payments](/reference/api/treasury) | Vaults, wallets, transfers, M-Pesa/Stripe rails, disbursements |
| [Trading & markets](/reference/api/trading) | Market data, orders, strategies, bridge and gateway routes |
| [Agents](/reference/api/agents) | Agent status, Morio, Elder Council, automation |
| [Platform & operations](/reference/api/platform) | Admin, metrics, health, feature flags |
| [Other surfaces](/reference/api/other) | Routes that do not fit the taxonomy above |

DAO-scoped resources are nested: `/api/v1/daos/:daoId/proposals`,
`/api/v1/daos/:daoId/members`, `/api/v1/daos/:daoId/treasury/...`, and so on. The
`_daoId` router applies `isAuthenticated` and DAO-id validation to everything beneath it.

## Real-time

Six WebSocket paths are registered centrally (`/ws/admin`, `/ws/gateway`, `/ws/coordinator`,
`/ws/morio`, `/ws/notifications`, `/ws/prices`). Event names, room permissions and the known
Socket.IO path collision are documented in [WebSocket events](/reference/websocket-events).

## Rate limits

Opt-in per route, Redis-backed, fail-open when Redis errors. Actual numbers in
[Rate limits](/developer/rate-limits).
